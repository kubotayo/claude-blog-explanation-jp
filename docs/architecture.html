1. システム概要

本システムは「クロール・生成バッチ」と「記事表示 Web アプリ」の2つのサブシステムで構成される。どちらも単一の Next.js プロジェクトに同居させ、Vercel 上にデプロイする。

3. データフロー詳細

3-1. バッチ処理フロー

Vercel Cron (6:00 JST)
  └─▶ GET /api/cron/crawl
        │
        ├─ 1. crawler.ts: claude.com/blog をクロールして記事URLリストを取得
        │
        ├─ 2. firestore.ts: crawl_log から処理済みURLを取得
        │
        ├─ 3. 差分（未処理URL）を抽出
        │
        └─ 4. 各未処理URLに対して順次処理:
              a. crawler.ts: 記事本文・メタ情報を取得
              b. generator.ts: Claude API に翻訳・解説・スコアリングを依頼
              c. firestore.ts: articles コレクションに保存
              d. firestore.ts: crawl_log に処理済みとして記録

3-2. Claude API への入出力

1回の API 呼び出しで翻訳・解説・メタ情報をすべて生成する。出力は JSON スキーマで構造化する。

// 入力（プロンプト概略）
{
  role: "user",
  content: `
    以下の Anthropic 公式ブログ記事を日本語に翻訳・解説してください。
    出力は指定の JSON スキーマに従ってください。

    # 原文
    タイトル: {originalTitle}
    著者: {author}
    カテゴリ: {category}
    公開日: {publishedAt}

    {originalContent}
  `
}

// 出力（JSON スキーマ）
{
  japaneseTitle: string,
  summary: string,                  // 3〜5行
  detailedExplanation: string,      // Markdown
  keyPointsEngineer: string[],      // 5〜8項目
  keyPointsBusiness: string[],      // 5〜8項目
  japanUseCases: string,            // Markdown
  targetAudience: ("engineer" | "business" | "general" | "researcher")[],
  importanceScore: "S" | "A" | "B" | "C",
  importanceReason: string          // 1〜2文
}

3-3. 表示フロー

ユーザーが / にアクセス
  └─▶ Next.js ISR: Firestore から articles を取得（importanceScore 降順）
        └─▶ ArticleCard × N を表示
              └─▶ ユーザーがカードをクリック
                    └─▶ /articles/[id] にアクセス
                          └─▶ Next.js ISR: Firestore から articles/{id} を取得
                                └─▶ ArticleDetail を表示（Markdown レンダリング）

6-2. vercel.json（Cron 設定）

{
  "crons": [
    {
      "path": "/api/cron/crawl",
      "schedule": "0 21 * * *"
    }
  ]
}

※ Vercel の Cron は UTC 基準。21:00 UTC = 06:00 JST（UTC+9）

Vercel Hobby プランの制限: Cron Functions は1日1回・実行時間60秒まで。初回遡及取得（100件超）は制限を超えるため、scripts/seed.mjs をローカルから手動実行する。

7. セキュリティ

7-1. Cron エンドポイントの保護

不正なリクエストによる API 乱用を防ぐため、Authorization ヘッダーで CRON_SECRET を検証する。Vercel Cron は自動的に Authorization: Bearer {CRON_SECRET} を付与する。

// /api/cron/crawl/route.ts
export async function GET(request: Request) {
  const authHeader = request.headers.get("authorization");
  if (authHeader !== `Bearer ${process.env.CRON_SECRET}`) {
    return new Response("Unauthorized", { status: 401 });
  }
  // ...
}

7-2. Firestore セキュリティルール

記事データは全公開読み取り。書き込みはサーバーサイド（API Routes）からのみ許可するため、クライアントからの直接書き込みを禁止する。

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // articles: 誰でも読み取り可能、書き込みは不可（サーバーサイドのみ）
    match /articles/{articleId} {
      allow read: if true;
      allow write: if false;
    }
    // crawl_log: 読み書き不可（サーバーサイドのみ）
    match /crawl_log/{logId} {
      allow read, write: if false;
    }
  }
}
サーバーサイドからの書き込みは Firebase Client SDK（サーバー上で動く Next.js API Routes）を使う。Admin SDK への移行は将来的な選択肢として保留。
